# Evaluation

This folder evaluates the RDF Time Series Sources (RDF-TSS) material of demo 11 on public water-conductivity data from [Waterinfo.be](https://www.waterinfo.be). The material is the specification (`../spec/spec.bs`), the vocabulary (`../vocabulary/tss.ttl`), the SHACL shapes (`../SHACL/`) and the metadata documents (`../metadata endpoint/`). The results are in [RESULTS.md](RESULTS.md).

| Folder | What it evaluates | Script | Results |
| --- | --- | --- | --- |
| `waterinfo/` | Retrieves the Waterinfo selection, and checks that each Waterinfo metadata document describes its data: column bindings, lexical forms, keys, readings, coverage and stored summaries (checks D1–D6). A self-test introduces 12 deliberate errors that the checks must find. | `fetch_waterinfo.py`, `check_waterinfo.py`, `selftest_waterinfo.py` | `waterinfo/results/`, `waterinfo/manifest.json` |
| `competency_questions/` | Eight competency questions (SPARQL), on a synthetic catalog and on the Waterinfo documents, with expected answers for the latter. | `evaluation_runner.py` | `competency_questions/results/` |
| `validation/` | The SHACL shapes on valid descriptions (the Waterinfo documents and the examples of the specification) and on 56 variants with one deliberate error or warning each. | `run_validation.py` (cases in `cases.py`) | `validation/results/` (one SHACL report per case in `reports/`) |
| `lifecycle/` | Growing sources over successive states: an RDF Message Log, a CSV data file and an Arrow IPC stream, built from real readings. It checks message dependencies, row messages, finalisation and byte-prefix preservation, runs 19 variants, and follows the sources over HTTP with Range requests from a local server. | `check_lifecycle.py` | `lifecycle/results/`, `lifecycle/fixtures/` |
| `software/` | The `rdftss` library (`../../../rdftss-python/`) on the Waterinfo metadata documents: it must read the same rows and values as `tss_reader.py`, report no SHACL violation or warning, and find every stored summary up to date. | `check_rdftss.py` | `software/results/` |

`tss_reader.py` is the reader that the scripts share. It reads a metadata document (Turtle, or an RDF Message Log as the merge of its messages) and the rows of each source, as the specification says. It covers the five source classes, CSV, Parquet and Arrow data files, time grids, baseline differences, RDF points and JSON rows. It reads what the evaluation needs; it is not a complete implementation.

## Reproducing

The reported runs used Python 3.14.6 and the versions in `requirements.txt`. Run these from this folder, in this order:

```bash
python -m pip install -r requirements.txt
cd waterinfo && python fetch_waterinfo.py && python check_waterinfo.py && python selftest_waterinfo.py && cd ..
cd competency_questions && python evaluation_runner.py && python evaluation_runner.py --waterinfo \
    --questions waterinfo_questions.yaml --expected waterinfo_expected.yaml \
    --output results/waterinfo_results.json && cd ..
cd validation && python run_validation.py && cd ..
cd lifecycle && python check_lifecycle.py && cd ..
python -m pip install ../../../rdftss-python
cd software && python check_rdftss.py && cd ..
```

`fetch_waterinfo.py` needs internet access: it requests the public KiWIS web service of Waterinfo.be, which needs no account or key. The other scripts run offline. `check_rdftss.py` needs the `rdftss` library, which is in this repository.

## Data

The retrieved data are not in the repository: `../data/` is excluded from version control. `fetch_waterinfo.py` writes the raw responses to `../data/raw/`, and the prepared data files to `../data/`. `waterinfo/manifest.json` records, for every file:

- the request URLs;
- the selection;
- the number of rows;
- the SHA-256 checksum.

Waterinfo may revise its records, so a later retrieval can differ from the one reported. The checksums show whether it does.

The lifecycle fixtures (`lifecycle/fixtures/`) are generated by `check_lifecycle.py` from 46 of these readings.

The factory document in `../metadata endpoint/` (`factory_conductivity_tss2.ttl`) is not part of the evaluation. Every script excludes it.
